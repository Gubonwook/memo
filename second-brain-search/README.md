# 세컨드 브레인 검색 개선: 자체 호스팅 LLM에 맞게 바꾸는 방법

2026-11-06

이 문서는 사람과 **자체 호스팅 LLM**이 함께 읽도록 썼습니다. LLM은 "LLM에게 시킬 일" 절과 "평가 방법" 절부터 읽으면 됩니다.

## 1. 목적과 전제

- 목적: 마크다운 노트(세컨드 브레인)의 검색 품질을 올린다.
- 전제 (확인되지 않은 것은 `?` 표시)
  - 노트는 마크다운 파일이고 Git으로 관리한다.
  - LLM은 자체 호스팅 API로만 쓸 수 있다. OpenAI 호환 형식(`/v1/chat/completions`)으로 추정한다 `?`
  - 임베딩 API가 있는지는 모른다 `?`
  - 작업 PC에는 GPU가 없다. 무거운 모델을 로컬로 돌리기 어렵다.
  - 노트 내용은 외부 서비스로 보내지 않는다(로컬 또는 자체 호스팅 안에서만 처리).
- 노트 언어는 한국어와 영어가 섞여 있다.

## 2. 먼저 알아둘 원리

검색 품질은 세 곳에서 갈립니다.

| 단계 | 하는 일 | 약하면 생기는 문제 |
|---|---|---|
| 색인 | 노트를 조각(청크)으로 자르고 키워드·벡터로 저장 | 조각이 너무 길거나 주제가 섞이면 엉뚱한 결과 |
| 검색 | 키워드(BM25)와 벡터를 합쳐 후보를 뽑음 | 키워드만 쓰면 동의어를 놓치고, 벡터만 쓰면 고유명사·약어를 놓침 |
| 재정렬·질의 확장 | LLM이 질문을 바꿔 쓰거나 후보 순서를 다시 매김 | 후보는 맞는데 순서가 나빠 못 찾음 |

자체 호스팅 LLM은 마지막 단계(질의 확장, 재정렬)에 가장 잘 맞습니다. 임베딩은 LLM과 별개의 모델이라 API가 있는지 먼저 확인해야 합니다.

## 3. 선택지 비교

### A. qmd를 그대로 쓰기 (로컬 모델)

[tobi/qmd](https://github.com/tobi/qmd): 로컬 마크다운 검색 CLI. 직접 README를 열어 확인한 내용입니다.

- 기능: `qmd search`(BM25), `qmd vsearch`(벡터), `qmd query`(BM25+벡터+질의 확장+LLM 재정렬). MCP 서버 제공(`qmd mcp`). MIT 라이선스.
- 모델: 임베딩 embeddinggemma-300M, 재정렬 qwen3-reranker-0.6b, 질의 확장 1.7B 모델. 모두 로컬 GGUF이고 첫 실행 때 내려받습니다.
- 설치: Node.js 22 이상 또는 Bun.

| 장점 | 단점 |
|---|---|
| 설치만 하면 바로 하이브리드 검색 | 기본 임베딩이 영어 중심이라 한국어가 약함 |
| 데이터가 밖으로 나가지 않음 | 모델을 처음에 내려받아야 함(사내망에서 막힐 수 있음 `?`) |
| MCP 서버가 있어 Claude Code 등에 바로 연결 | GPU 없이는 질의 확장·재정렬이 느릴 수 있음 `?` |
| 스타가 많고 관리가 활발함 | 자체 호스팅 LLM을 재정렬·확장에 쓰는 설정이 있는지 확인하지 못함 `?` |

### B. qmd + 다국어 임베딩으로 교체

README에 따르면 `QMD_EMBED_MODEL`을 Qwen3-Embedding-0.6B로 바꾸면 한국어를 포함한 다국어를 지원하고, 바꾼 뒤에는 `qmd embed -f`로 다시 임베딩해야 합니다. 한국어 품질은 직접 확인하지 않았습니다.

| 장점 | 단점 |
|---|---|
| A의 장점을 유지하면서 한국어 개선 | 모델을 추가로 내려받아야 함 |
| 설정 한 줄 변경 | 전체 노트를 다시 임베딩해야 하고 CPU에서는 오래 걸릴 수 있음 `?` |

### C. 직접 만드는 가벼운 파이프라인 (자체 호스팅 LLM 활용)

SQLite 한 파일에 BM25와 벡터를 저장하고, 질의 확장과 재정렬은 자체 호스팅 LLM API로 처리하는 구성입니다.

- 키워드 검색: SQLite FTS5. 한국어는 기본 토크나이저가 어절 단위라 약하므로 `trigram` 토크나이저를 쓰는 편이 낫습니다(SQLite 3.34 이상).
- 벡터 검색: 자체 임베딩 API가 있으면 그것을 쓰고, 없으면 작은 로컬 모델을 CPU로 돌립니다 `?`
- 합치기: 두 순위를 RRF(Reciprocal Rank Fusion)로 합산합니다.
- 질의 확장: 자체 호스팅 LLM이 질문을 동의어·영문 용어를 포함한 3~5개 검색어로 바꿉니다.
- 재정렬: 상위 20개 후보를 LLM에 보여 주고 관련도 순으로 다시 정렬시킵니다.

| 장점 | 단점 |
|---|---|
| 자체 호스팅 LLM을 그대로 활용 | 직접 만들고 유지해야 함 |
| 데이터와 LLM 호출이 모두 사내 안에 머묾 | 임베딩 API가 없으면 벡터 부분이 막힘 |
| 한국어 처리(trigram, 영문 병기 확장)를 직접 조절 가능 | LLM 호출이 늘어 검색이 느려지고 비용·부하가 생김 |

### D. BM25만 + LLM 질의 확장 (가장 단순)

벡터 없이 FTS5 키워드 검색에 LLM 질의 확장만 붙이는 방식입니다.

| 장점 | 단점 |
|---|---|
| 의존성이 거의 없고 GPU·임베딩이 필요 없음 | 의미 기반 검색(표현이 다른 같은 뜻)은 약함 |
| 하루 안에 만들 수 있음 | 확장 품질이 LLM에 달려 있음 |

### E. 다른 오픈소스 (미검증)

[loci](https://github.com/helenk7079/loci)(BM25+벡터, 섹션 단위 인용, MCP), [arkangelai/second-brain](https://github.com/arkangelai/second-brain), [Vivek-122005/Second-Brain](https://github.com/Vivek-122005/Second-Brain)은 검색 결과의 제목과 설명만 봤고 내용·품질·라이선스는 열어 보지 않았습니다. 후보로만 보고, 쓰기 전에 직접 확인하세요.

## 4. 추천 순서

1. **노트 정리부터** (비용 0): 파일마다 frontmatter에 `description`(한 줄), `aliases`, 태그를 넣고, 한국어와 영어 용어를 함께 적고, 한 노트에는 한 주제만 둡니다.
2. **D로 시작**: BM25 + LLM 질의 확장. 하루면 만들고 효과를 바로 잴 수 있습니다.
3. **임베딩 API 확인 후 C로 확장**: 임베딩이 있으면 벡터와 RRF를 더합니다.
4. 사내망에서 모델 내려받기가 되고 설치가 허용되면 **B(qmd + Qwen3-Embedding)** 를 병행해 비교합니다.

어느 쪽이든 아래 평가 방법으로 숫자를 보고 정합니다.

## 5. 평가 방법 (이게 있어야 개선인지 알 수 있음)

1. 실제로 찾고 싶었던 질문 20개를 만들고, 각 질문의 정답 노트(들)를 손으로 적습니다.
2. 각 방식으로 상위 5개를 뽑아 **정답이 5위 안에 있는 비율(recall@5)** 과 **정답의 순위**를 표로 비교합니다.
3. 한국어 질문, 영어 질문, 약어·고유명사 질문을 섞습니다.
4. 방식을 바꿀 때마다 같은 20개로 다시 돌립니다.

## 6. LLM에게 시킬 일 (자체 호스팅 LLM용 프롬프트 초안)

아래를 그대로 LLM에 붙여 넣어도 됩니다.

```
너는 내 마크다운 노트 검색을 개선하는 일을 돕는다.
제약: 노트 내용은 외부로 보내지 않는다. GPU는 없다. LLM은 자체 호스팅 API(OpenAI 호환 추정)만 쓴다.
노트는 한국어·영어 혼용이며 Git으로 관리한다.

1. 이 문서의 선택지 중 D(BM25+질의 확장)를 먼저 구현하는 계획을 세워라.
   - SQLite FTS5(trigram 토크나이저)로 색인하는 스크립트
   - 질문을 받아 동의어·영문 용어 포함 검색어 3~5개를 만드는 프롬프트
   - 결과를 RRF로 합치고 상위 5개를 출력하는 CLI
2. 각 단계에서 내가 확인해야 할 것(임베딩 API 유무, 설치 허용 범위 등)을 질문 목록으로 정리해라.
3. 확인되지 않은 사실을 사실처럼 쓰지 마라. 모르면 "확인 필요"라고 적어라.
4. 구현 후 20개 질문 평가표(recall@5)를 만드는 방법을 제안해라.
```

## 7. 다른 AI에게 추천받을 때 묻는 방법

AI에게 "검색 개선해줘"라고만 하면 일반론이 나옵니다. 아래 정보를 같이 주면 구체적인 답이 나옵니다.

- 노트 개수와 평균 길이, 언어, 저장 도구(Obsidian, Git 등)
- 지금 쓰는 검색 방식과 실패 사례 3개(질문, 기대한 노트, 실제 결과)
- 제약 조건(GPU 없음, 외부 전송 금지, 사용 가능한 API 종류)
- 원하는 결과물(설치 순서, 스크립트, 평가표 중 무엇인지)
- "확인하지 못한 것은 확인 필요라고 표시하고, 출처 링크를 달아라"라는 요구
