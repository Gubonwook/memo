SevenNet으로 무엇을 할 수 있나

SevenNet은 서울대 MDIL(한승우 교수 그룹)이 개발한 equivariant GNN 원자간 퍼텐셜 패키지입니다. 이 문서는 SevenNet의 동작 원리, 사전학습 모델 고르는 법, 돌릴 수 있는 시뮬레이션, 학습·fine-tuning 절차, 그리고 RTX PRO 6000 Blackwell(96GB) 세팅 방법을 그림 위주로 정리합니다. GitHub 저장소와 공식 문서를 기준으로 썼습니다(2026년 11월 확인).

1SevenNet은 어떻게 동작하나

원자 구조를 그래프로 바꿉니다. 원자는 노드가 되고, cutoff 반경 안에 있는 원자 쌍은 엣지가 됩니다. 그 위에서 회전에 대해 equivariant한 메시지 패싱을 여러 층 반복하면 원자마다 에너지가 나오고, 이를 모두 더하면 전체 에너지 E가 됩니다. 힘과 응력은 E를 위치와 변형으로 미분해서 얻습니다. 모델의 뼈대는 NequIP 구조입니다.

SevenNet만의 특징
  • 공간 분할 병렬 MD: 메시지 패싱 층마다 이웃 GPU와 정보를 주고받는 알고리즘으로, LAMMPS에서 여러 GPU로 대형 계를 돌릴 수 있습니다(JCTC 2024).
  • Multi-fidelity / multi-task 학습: DFT 설정(PBE+U, r²SCAN, ωB97M-V 등)이 서로 다른 데이터셋을 한 모델로 학습하고, 추론할 때 modal로 원하는 기준을 고릅니다(JACS 2024).
  • 망각 방지 fine-tuning(reEWC), GPU D3 분산 보정, 텐서곱 가속기(FlashTP · cuEquivariance · OpenEquivariance · LunaTP)를 지원합니다.

2전체 지도: 모델 → 엔진 → 시뮬레이션

SevenNet을 쓰는 경로는 세 가지입니다. ① 사전학습 모델을 그대로 쓰기, ② 내 DFT 데이터로 fine-tuning하기, ③ 처음부터 학습하기. 어느 경로로 만든 모델이든 같은 실행 엔진에 꽂아서 씁니다.

3사전학습 모델 고르기

공식 권장 모델은 SevenNet-Omni입니다. 15개 공개 ab initio 데이터셋을 함께 학습해서 결정, 분자, 표면, 계면, MOF를 모두 다룹니다. 계가 크고 속도가 중요하면 Omni를 지식 증류해 만든 Nano가 대안입니다.

Multi-task(modal)란?

Omni는 한 네트워크가 여러 DFT 기준을 함께 배웁니다. 추론할 때 modal로 “어느 데이터셋의 DFT 설정에 맞춘 답을 낼지”를 고릅니다. 같은 구조라도 task를 바꾸면 PBE+U 결과처럼, 또는 r²SCAN 결과처럼 출력합니다.

4돌릴 수 있는 시뮬레이션

SevenNet 자체는 “에너지·힘·응력을 빠르게 계산하는 계산기”입니다. 따라서 ASE나 LAMMPS가 지원하는 시뮬레이션은 대부분 그대로 돌릴 수 있습니다. DFT 대비 수천 배 빠르기 때문에, DFT로는 못 하던 크기와 시간 규모가 열립니다.

ASETorchSim (배치)

NVE, NVT(Langevin·Nosé–Hoover), NPT를 돌릴 수 있습니다. 용융·결정화, 비정질 생성(melt-quench), 확산계수, RDF 분석이 가능하고, LAMMPS에서는 다중 GPU로 수십만 원자 규모까지 갑니다.

ASE의 NEB·CI-NEB·Dimer로 전이상태를 탐색합니다. 공공(vacancy)이나 이온 확산, 상전이 경로, 표면 반응 단계별 장벽을 구할 수 있습니다. 이미지가 많아도 빠르게 돌아갑니다.

ASE

표면 흡착 · 계면

슬랩 위 분자 흡착에너지, 흡착 자리별 비교, 표면·계면 에너지를 계산합니다. 물리흡착이 중요한 계는 D3를 함께 켜는 것이 좋습니다.

ASE+D3

5학습 · Fine-tuning 파이프라인

사전학습 모델의 정확도가 부족한 계라면, DFT를 수백~수천 개 정도 계산해서 fine-tuning하는 것이 일반적인 경로입니다. CLI 다섯 개로 처음부터 끝까지 진행합니다.

reEWC: “잊지 않는” fine-tuning

내 계에 맞춰 fine-tuning하면 그 계에서는 정확해지지만, 원래 잘 맞추던 다른 영역의 정확도가 떨어지기 쉽습니다(catastrophic forgetting). reEWC는 두 가지 장치로 이를 막습니다.

제약: reEWC는 현재 single-modal 모델(SevenNet-0, Nano 등)에만 쓸 수 있습니다. Omni 같은 multi-task 모델은 아직 지원하지 않습니다. Fisher 행렬은 SevenNet이 계산해 주지 않으므로 직접 준비해야 하고, DDP 학습도 지원하지 않습니다.

7바로 쓰는 코드 예시

pip install sevenn
pip install sevenn[cueq12]     # cuEquivariance 가속 (CUDA 12.x)
pip install sevenn[torchsim]   # 배치 시뮬레이션 (Python ≥ 3.12)
sevenn cp 7net-omni            # 모델 개요 확인
from ase.io import read
from ase.optimize import BFGS
from ase.filters import FrechetCellFilter
from sevenn.calculator import SevenNetCalculator

atoms = read("POSCAR")
atoms.calc = SevenNetCalculator(model="7net-omni", modal="mpa")
BFGS(FrechetCellFilter(atoms)).run(fmax=0.02)   # 셀까지 함께 relax
print(atoms.get_potential_energy())
from ase import units
from ase.md.langevin import Langevin
from ase.md.velocitydistribution import MaxwellBoltzmannDistribution
from sevenn.calculator import SevenNetCalculator

atoms.calc = SevenNetCalculator(model="7net-omni", modal="mpa")
MaxwellBoltzmannDistribution(atoms, temperature_K=1200)
dyn = Langevin(atoms, 2*units.fs, temperature_K=1200, friction=0.01,
               trajectory="md.traj")
dyn.run(50000)   # 100 ps
from ase.mep import NEB
from ase.optimize import FIRE
from ase.io import read
from sevenn.calculator import SevenNetCalculator

IS, FS = read("IS.vasp"), read("FS.vasp")
images = [IS] + [IS.copy() for _ in range(7)] + [FS]
for im in images:
    im.calc = SevenNetCalculator(model="7net-omni", modal="mpa")
neb = NEB(images, climb=True)
neb.interpolate(method="idpp")
FIRE(neb).run(fmax=0.05)
from sevenn.calculator import SevenNetD3Calculator

# 흡착에너지 E_ads = E(slab+mol) − E(slab) − E(mol), 세 구조 모두 같은 calc
calc = SevenNetD3Calculator(model="7net-omni", modal="mpa",
                            functional_name="pbe", damping_type="damp_bj",
                            device="cuda")   # D3는 CUDA GPU 필수
for a in (slab_mol, slab, mol):
    a.calc = calc
E_ads = (slab_mol.get_potential_energy()
         - slab.get_potential_energy() - mol.get_potential_energy())

D3를 쓸 때는 모델의 학습 범함수와 같은 functional_name을 지정해야 합니다. 예를 들어 SevenNet-0이면 pbe입니다. Omni의 task별로 어떤 D3 범함수를 써야 하는지는 문서에 별도 안내가 없으니, 해당 task가 어떤 범함수로 학습됐는지 확인하고 고르세요.

# 1) 배포
sevenn get_model 7net-omni --modal mpa                  # serial (e3gnn)
sevenn get_model 7net-omni --modal mpa --use_mliap      # ML-IAP

# 2) LAMMPS 입력 (단일 GPU, Torch 경로)
units       metal
atom_style  atomic
pair_style  e3gnn
pair_coeff  * * deployed_serial.pt Hf O

# + D3 결합
pair_style  hybrid/overlay e3gnn d3 9000 1600 damp_bj pbe
pair_coeff  * * e3gnn deployed_serial.pt Hf O
pair_coeff  * * d3    Hf O

다중 GPU로 돌리려면 e3gnn/parallel을 쓰고 pair_coeff * * {층 수} {배포 디렉토리} 원소… 형식으로 적습니다. 서브도메인 중 원자가 하나도 없는 곳이 생기면 오류가 나므로 fix balance를 권장합니다.

sevenn preset fine_tune > input.yaml   # checkpoint: 7net-omni 등 지정
# input.yaml에서 데이터 경로, (multi-task면) modal 설정
sevenn train input.yaml -s --enable_flash
sevenn inference checkpoint_best.pth test_structures/*   # 검증
sevenn get_model checkpoint_best.pth                     # LAMMPS 배포

9주의점 체크리스트

  • D3: CUDA GPU(compute capability ≥ 6.0)가 필요하고 CPU에서는 돌지 않습니다. 한 번에 최대 46,340 원자까지만 계산되며, 다중 GPU나 다중 코어 병렬은 지원하지 않습니다.
  • multi-task 모델을 쓸 때는 modal을 반드시 지정해야 하고, LAMMPS로 배포할 때도 --modal이 필요합니다.
  • LAMMPS 버전이 경로마다 다릅니다. Torch 경로는 stable_2Aug2023_update3, ML-IAP 경로는 stable_22Jul2025_update4를 권장합니다.
  • ML-IAP 다중 rank 실행은 아직 검증이 부족합니다. 다중 GPU라면 Torch 경로의 e3gnn/parallel을 쓰세요.
  • cuEquivariance와 LunaTP는 ML-IAP 경로에서만 쓸 수 있습니다.
  • v0.13에서 rescale layer의 기본 dtype이 double로 바뀌었습니다. 이전 버전과 결과를 비교할 때는 SEVENN_SHIFT_SCALE_DTYPE 설정을 확인하세요.
  • MLIP는 학습 분포 밖(극단적 압축, 결합이 끊어지는 순간, 희귀 원소 조합)에서 오차가 급증할 수 있습니다. MD 중 원자가 뭉치거나 에너지가 튀면 의심해야 합니다.

10RTX PRO 6000 Blackwell (96GB)에서 세팅하기

결론: 세팅 가능합니다. 다만 Blackwell 워크스테이션 GPU는 compute capability 12.0(sm_120)이라서 CUDA 12.8 이상과 sm_120 커널이 포함된 PyTorch(cu128 이상 휠)가 꼭 필요합니다. SevenNet 본체는 PyTorch 위에서 돌기 때문에 PyTorch만 맞으면 그대로 동작합니다. 가속기와 LAMMPS는 빌드할 때 대상 아키텍처를 12.0으로 지정해야 합니다.

아래 내용은 SevenNet·FlashTP·LAMMPS 소스 코드와 공개 문서·포럼을 확인해서 정리한 것입니다. 실제 RTX PRO 6000에서 직접 돌려 검증한 결과는 아니므로, 설치 후 check_env.py로 반드시 확인하세요.

GPU D3 (ASE)✅ 첫 실행 때 JIT 컴파일코드가 감지한 아키텍처 12.0을 자동으로 추가합니다. 컴파일에 nvcc 12.8+가 필요합니다. TORCH_CUDA_ARCH_LIST를 직접 지정할 때는 12.0을 꼭 포함하세요.
FlashTP✅ README에 Blackwell 동작 명시최고 성능을 내려면 CUDA_ARCH_LIST="120"으로 재빌드하세요(빌드 시점에 GPU가 있으면 자동 감지).
cuEquivariance⚠️ sm_120 공식 명시는 확인 못 함설치 후 check_env.py로 e3nn 결과와 일치하는지 확인하세요. 문제가 있으면 FlashTP나 OEq를 대신 쓰면 됩니다.
OpenEquivariance · LunaTP⚠️ JIT 방식이라 원리상 가능직접 검증 필요. LunaTP는 실험적 기능이고 PyTorch ≥ 2.8이 필요합니다.
LAMMPS: Torch🔧 빌드 설정 필요sevenn patch_lammps가 C++17로 자동 패치합니다. D3를 넣을 때는 TORCH_CUDA_ARCH_LIST="12.0"을 지정하세요.
LAMMPS: ML-IAP🔧 빌드 설정 필요cmake에 -D Kokkos_ARCH_BLACKWELL120=ON을 추가하세요(내장 Kokkos 4.6.2가 지원).

96GB를 잘 쓰는 법

🧱 큰 계를 한 장에

메모리가 크기 때문에 다중 GPU 병렬 없이도 단일 GPU e3gnn이나 ML-IAP로 큰 셀을 돌릴 수 있습니다. 실제로 몇 원자까지 되는지는 모델 크기와 밀도에 따라 다르므로 check_env.py --natoms로 직접 재 보세요.

🔀 MIG로 나눠 쓰기

GPU 한 장을 최대 4개 인스턴스로 나눌 수 있습니다. 흡착 자리 스크리닝처럼 작은 계산을 여러 개 동시에 돌릴 때 유용합니다. 큰 MD 하나를 돌릴 때는 MIG를 끄세요.

📦 TorchSim 배치

구조 수백 개를 한 번에 relax하는 고처리량 작업에서 큰 메모리가 그대로 처리량으로 이어집니다.

⚠️ 그래도 남는 한계

D3는 메모리와 관계없이 한 번에 최대 46,340 원자까지만 계산됩니다. NVLink가 없어서 카드 여러 장을 병렬로 쓰면 통신이 PCIe를 탑니다. FP64 성능이 낮지만, SevenNet은 기본이 FP32라서 영향이 적습니다.

설치 순서

같은 내용을 스크립트로 묶은 setup_blackwell.sh와 검증용 check_env.py를 GitHub 폴더에 함께 올려 두었습니다.

# 드라이버 R570 이상, compute_cap 12.0 확인
nvidia-smi --query-gpu=name,driver_version,compute_cap,memory.total --format=csv

# JIT·소스 빌드(D3, FlashTP, LAMMPS)를 하려면 nvcc 12.8 이상
nvcc --version          # 12.8 미만이면 CUDA toolkit 12.8+ 설치
export CUDA_HOME=/usr/local/cuda-12.8
conda create -n sevenn python=3.12 -y     # TorchSim은 3.12 이상 필요
conda activate sevenn
pip install torch --index-url https://download.pytorch.org/whl/cu128

python -c "import torch;print(torch.__version__, torch.cuda.get_arch_list())"
# → 목록에 'sm_120'이 있어야 함
pip install sevenn
echo 'export TORCH_CUDA_ARCH_LIST="12.0"' >> ~/.bashrc   # D3/LAMMPS JIT 대상 고정
source ~/.bashrc
sevenn cp 7net-omni     # 모델 다운로드와 개요 확인
# cuEquivariance (CUDA 12.x 기준; cu130 휠이면 cueq13)
pip install "sevenn[cueq12]"

# FlashTP (소스 빌드)
git clone https://github.com/SNU-ARC/flashTP.git && cd flashTP
pip install -r requirements.txt
CUDA_ARCH_LIST="120" pip install . --no-build-isolation   # exit 137이면 MAX_JOBS=4

# 기타
pip install "sevenn[oeq]" "sevenn[torchsim]"
python check_env.py --model 7net-omni --modal mpa --natoms 5000
# 1) sm_120 포함 여부  2) 가속기 사용 가능 여부
# 3) 가속기 결과가 e3nn과 일치하는지(ΔE, ΔF)  4) D3 JIT  5) ms/step · peak 메모리
pip install "sevenn[mliap12]"
git clone https://github.com/lammps/lammps lammps-mliap && cd lammps-mliap
git checkout stable_22Jul2025_update4
cmake -B build -D CMAKE_BUILD_TYPE=Release \
  -D CMAKE_CXX_COMPILER=$(pwd)/lib/kokkos/bin/nvcc_wrapper \
  -D PKG_KOKKOS=ON -D Kokkos_ENABLE_CUDA=ON \
  -D Kokkos_ARCH_BLACKWELL120=ON \
  -D BUILD_MPI=ON -D PKG_ML-IAP=ON -D PKG_ML-SNAP=ON \
  -D MLIAP_ENABLE_PYTHON=ON -D PKG_PYTHON=ON -D BUILD_SHARED_LIBS=ON cmake
cmake --build build -j 16

sevenn get_model 7net-omni --modal mpa --use_mliap --enable_cueq

Kokkos_ARCH_BLACKWELL120 한 줄이 공식 문서 예시에 추가한 부분입니다. 나머지 옵션은 SevenNet 문서와 같습니다.

export TORCH_CUDA_ARCH_LIST="12.0"
git clone https://github.com/lammps/lammps.git lammps_sevenn \
    --branch stable_2Aug2023_update3 --depth=1
sevenn patch_lammps ./lammps_sevenn --d3 --enable_flash   # 필요한 옵션만
cd lammps_sevenn && mkdir build && cd build
cmake ../cmake -DCMAKE_PREFIX_PATH=$(python -c 'import torch;print(torch.utils.cmake_prefix_path)')
make -j 16

2023년 LAMMPS 버전을 최신 libtorch(cu128)와 엮는 조합이라서 빌드 오류가 날 가능성이 있습니다. 문제가 생기면 ML-IAP 경로를 먼저 시도해 보세요.
